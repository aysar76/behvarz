# ردیاب شاخص‌های پایلوت (Metrics Tracker)

**کاربرد:** ثبت هفتگی شاخص‌های خروج فاز ۹. همه مقادیر از **رویدادهای واقعی** سیستم استخراج می‌شوند (جدول‌ها و لاگ‌های پلتفرم)، نه برآورد.

---

## ۱. تعریف و فرمول

| شاخص                         | فرمول / تعریف                                                                                                                |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| WAU                          | کاربران یکتایی که در ۷ روز گذشته حداقل یک اقدام معنادار داشته‌اند (ثبت/پاسخ/راهکار/تجربه/حلقه/اعلان‌خوانی) ÷ کل کاربران فعال |
| MAU                          | همان در ۳۰ روز گذشته                                                                                                         |
| WAU/MAU                      | نسبت WAU به MAU (هدف ≥ ۶۰٪)                                                                                                  |
| D30                          | کاربرانی که ۳۰ روز پس از ثبت‌نام دوباره وارد شده‌اند ÷ کل ثبت‌نام‌شدگان (هدف ≥ ۳۰٪)                                          |
| نرخ پاسخ ۴۸ساعته             | مسائل با اولین پاسخ < ۴۸ ساعت از ثبت ÷ کل مسائل (هدف ≥ ۷۰٪)                                                                  |
| تبدیل به راهکار              | مسائل با وضعیت `solved` و جمع‌بندی ÷ کل مسائل (هدف ≥ ۵۰٪)                                                                    |
| سفیر فعال در استان           | سفیرانی که در ۷ روز گذشته ≥ ۳ اقدام ثبت کرده‌اند (هدف ≥ ۲ در هر استان)                                                       |
| تأیید صریح «راحت‌تر شدن کار» | مصاحبه‌شوندگانی که سؤال ۹ را «بله» پاسخ داده‌اند ÷ کل مصاحبه‌شوندگان (هدف ۱۰۰٪)                                              |
| اثر ملموس ثبت‌شده            | تعداد تجربه‌های دارای «اجرای مجدد» با نتیجه ثبت‌شده (هدف ≥ ۱۰)                                                               |

## ۳. منبع داده‌ها (از کد/پایگاه)

- مسائل، پاسخ‌ها، زمان‌ها: جداول `Problem` / `ProblemAnswer` / `ProblemStatusChange`.
- تجربه و اجرای مجدد: `Experience` / `ExperienceReuse` (با نتیجه).
- نشست/بازگشت: `Session` (آخرین فعالیت) و `AuditLog`.
- داده‌های استخراجی توسط تیم عامل در محیط پایلوت (توسعه: `dev.db`) و به‌صورت SQL/مشاهده جداول ثبت می‌شود.
- **توجه:** همه کوئری‌ها فقط بر روی شناسه‌های ناشناس؛ هیچ استخراج داده بیمار انجام نمی‌شود.

## ۴. تصمیم هفتگی

- هر هفته خلاصه یک‌صفحه‌ای (این جدول) در جلسه تیم عامل بررسی می‌شود.
- شاخص زیر هدف → شناسایی علت ریشه‌ای + اقدام کنترلی (نه تغییر سلیقه‌ای).
- پایان هفته ۸: مقایسه با جدول هدف → تصمیم دروازه رشد (سبز/زرد/قرمز طبق `pilot-plan.md`).

## ۵. پایه (هفته ۰)

مقادیر پایه پیش از شروع ثبت می‌شوند (همه صفر برای کاربران جدید) تا رشد معتبر اندازه‌گیری شود. در پایلوت، محتوای اولیه سفیران (تجربه‌های آغازگر) بخشی از داده پایه است و در شاخص «اثر ملموس» فقط اجرای مجدد توسط **کاربر دیگر** شمارش می‌شود.
