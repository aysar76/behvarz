# پشتیبان‌گیری و بازیابی (Backup & Restore)

**وضعیت:** فاز ۱۳ — سخت‌سازی، مقیاس و استقرار پایدار
**تاریخ:** مهر ۱۴۰۵

پلتفرم در فاز ۱۳ روی SQLite (تک‌نمونه) اجرا می‌شود؛ فایل دیتابیس از طریق متغیر
`DATABASE_URL` مشخص می‌شود. این سند روش پشتیبان‌گیری و بازیابی واقعی را توضیح می‌دهد.

---

## ۱. ابزارها

- `scripts/backup.mjs` — پشتیبان‌گیری با API `backup()` خود better-sqlite3 (اسنپ‌شات سازگار
  حتی در حین اجرا؛ نیازی به توقف سرویس نیست).
- `scripts/restore.mjs` — بازیابی با بررسی یکپارچگی (`integrity_check`) پیش از جایگزینی.

معادل `pnpm`:
- `pnpm backup` → `node scripts/backup.mjs`
- `pnpm restore <file>` → `node scripts/restore.mjs <file>`

## ۲. پشتیبان‌گیری

```bash
# پشتیبان‌گیری به پوشه پیش‌فرض backups/
pnpm backup

# پشتیبان‌گیری به پوشه مشخص و دیتابیس مشخص
node scripts/backup.mjs --out /var/backups/behvarz --db /var/lib/behvarz/data.db
```

خروجی: فایلی به شکل `behvarz-<timestamp>.db` در پوشه مقصد.

### نکته‌ها

- اگر `--db` داده نشود، از `DATABASE_URL` (با حذف پیشوند `file:`) یا `./dev.db` استفاده می‌شود.
- برای Production بهتر است خروجی روی حجم جداگانه/فضای ابری آپلود شود (از محدوده فاز ۱۳ خارج است؛
  به‌صورت دستی قابل اجراست).
- `dev.db` و هر `*.db` در گیت ایگنور شده‌اند؛ پشتیبان‌ها را در گیت commit نکنید.

## ۳. بازیابی (آزمایش‌شده)

> **قبل از بازیابی، برنامه باید متوقف باشد** تا فایل دیتابیس قفل نباشد (SQLite).

```bash
# ۱) سرویس را متوقف کنید
# ۲) بازیابی
pnpm restore backups/behvarz-2026-09-05T15-16-00-163Z.db

# بازیابی به دیتابیس مشخص
node scripts/restore.mjs /var/backups/behvarz/behvarz-*.db --db /var/lib/behvarz/data.db

# ۳) سرویس را دوباره شروع کنید
```

اسکریپت بازیابی پیش از جایگزینی، `integrity_check` فایل پشتیبان را اجرا می‌کند؛ اگر سالم نباشد
خروج ناموفق می‌دهد و دیتابیس جاری دست‌نخورده می‌ماند.

## ۴. آزمایش عملی Restore (در فاز ۱۳ انجام شد)

برای اثبات قابلیت بازیابی، یک دیتابیس آزمایشی ساخته شد، یک ردیف درج شد، پشتیبان گرفته شد،
ردیف حذف شد، سپس بازیابی شد و داده بازگشت (شمارش ردیف و مقدار تایید شد). نتیجه: **Restore به‌صورت
عملی آزمایش شده و سالم است.** دستورالعمل دقیق در `docs/phase-reports/phase-13-hardening.md`.

## ۵. برنامه پیشنهادی

| بازه | اقدام |
| ---- | ----- |
| روزانه | `pnpm backup` (کران‌جاب) به حجم جداگانه |
| هفتگی | تست بازیابی در محیط آزمایشی (نه Production) |
| ماهانه | مرور برش پشتیبان‌ها و اعمال Retention |

> امنیت پشتیبان‌ها: فایل‌های `*.db` داده حساس دارند؛ در Production باید دسترسی محدود و در صورت
> امکان رمزنگاری در محل ذخیره انجام شود.
